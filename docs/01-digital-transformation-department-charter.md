# ميثاق قسم التحول الرقمي

## رسالة القسم
قيادة وتنظيم التحول الرقمي داخل الشركة عبر توحيد الإجراءات، تحسين جودة البيانات، متابعة تنفيذ Odoo، بناء المؤشرات، وتمكين الأقسام من العمل بطريقة رقمية قابلة للقياس.

## رؤية القسم
أن تصبح الشركة خلال 2027 مؤسسة تعتمد على بيانات موثوقة وإجراءات موحدة وأنظمة مترابطة تدعم النمو في التجزئة والمشاريع والجملة.


## المبدأ الحاكم للقسم
قسم التحول الرقمي لا يقيس نجاحه بعدد الأنظمة التي تم تركيبها، بل بمدى قدرة الشركة على العمل بإجراءات موحدة وبيانات موثوقة ومسؤوليات واضحة وتقارير تساعد الإدارة على اتخاذ القرار في الوقت المناسب. لذلك يجب أن يكون أي نظام أو تقرير أو أتمتة مرتبطًا بإجراء معتمد ومالك بيانات واضح ومؤشر قابل للقياس.

## نطاق العمل
| البند | الوصف |
|---|---|
| الأنظمة | Odoo ERP، Onyx Pro مرحليًا، Power BI، n8n، PBX/WhatsApp/SIP عند ارتباطها بالعمليات |
| العمليات | البيع، المشاريع، الإنتاج، المستودعات، المشتريات، المالية، خدمة العملاء، متابعة العملاء، المكتب الفني، الموارد البشرية |
| البيانات | العملاء، المنتجات، SKU، الأسعار، الموردون، المخزون، الصلاحيات، البيانات المالية |
| التقارير | تقارير أسبوعية وشهرية ولوحات مؤشرات تنفيذية وتشغيلية |

## مسؤوليات القسم
- إدارة خطة التحول الرقمي والحوكمة والتقارير.
- متابعة مشروع Odoo وتوثيق المتطلبات والتغييرات والاختبارات.
- قيادة توثيق الإجراءات وتحسينها بالتنسيق مع ملاك العمليات.
- تنظيم تنظيف البيانات واعتمادها قبل الترحيل، دون تحمل مسؤولية صحة بيانات القسم بدل مالكها.
- إعداد خطة التدريب والتبني وقياس الاستخدام.
- بناء قائمة مبادرات الأتمتة والتقارير الذكية بعد استقرار الإجراء والبيانات.

## ما لا يدخل ضمن مسؤوليات القسم
- تنفيذ الأعمال التشغيلية اليومية بدل الأقسام.
- إدخال أو تصحيح البيانات نيابة عن ملاك البيانات بشكل دائم.
- اعتماد سياسات مالية أو تجارية دون الإدارة المختصة.
- قبول تغييرات نطاق من مورد Odoo دون Change Request معتمد.
- إدارة البنية التحتية التقنية اليومية إذا كانت ضمن تقنية المعلومات.

## العلاقة مع الإدارة العليا
الإدارة العليا تعتمد الخطة والأولويات والموارد والتغييرات الجوهرية، وتوفر الغطاء الإداري لإلزام الأقسام بالمشاركة. يرفع مدير التحول الرقمي تقريرًا أسبوعيًا مختصرًا وتقريرًا شهريًا تفصيليًا.

## العلاقة مع الأقسام الأخرى
كل قسم يعيّن مالك عملية ومالك بيانات وKey User وبديل. قسم التحول الرقمي ينسق ويوثق ويتابع، والقسم المختص يعتمد صحة الإجراء والبيانات ويلتزم بجدول التدريب والاختبار.

## العلاقة مع مورد Odoo
التواصل مع المورد يكون عبر قناة رسمية، وكل اجتماع ينتج عنه محضر، سجل قرارات، وسجل إجراءات. لا تعد أي ملاحظة أو اتفاق شفهي ملزمًا ما لم يوثق خلال 24 ساعة ويتم تأكيده كتابيًا.

## صلاحيات مدير التحول الرقمي
| الصلاحية | الحدود |
|---|---|
| طلب البيانات من الأقسام | ضمن نطاق الخطة وبجداول زمنية معتمدة |
| جدولة ورش العمل | بالتنسيق مع مديري الأقسام ودون تعطيل التشغيل الحرج |
| تصعيد التأخير | للإدارة العليا عند تجاوز الموعد أو عدم الالتزام |
| رفض رفع بيانات غير معتمدة | إلى أن تعتمد من مالك البيانات |
| إيقاف تغيير غير موثق | حتى استكمال نموذج Change Request |
| توحيد التقارير | تحديد مصدر ومالك وتكرار لكل مؤشر قبل نشره |
| إصدار التقارير | أسبوعيًا وشهريًا حسب القالب المعتمد |

## آلية استقبال الطلبات من الأقسام
| الخطوة | الوصف | الزمن المستهدف |
|---|---|---|
| تسجيل الطلب | نموذج موحد: الهدف، القسم، الأثر، الأولوية، المالك | يوم عمل |
| فرز أولي | تصنيف: Odoo، بيانات، تقرير، أتمتة، إجراء، تدريب | يومان |
| تقييم | أثر، تعقيد، اعتماد مطلوب، مورد مطلوب، مخاطر | 3 أيام عمل |
| قرار | تنفيذ سريع، إدراج في Backlog، تحويل للمورد، أو رفض مسبب | أسبوع |

## آلية اعتماد التغييرات
أي تغيير في نطاق Odoo أو الإجراءات أو التقارير يمر عبر: طلب تغيير، تحليل أثر على الوقت والتكلفة والبيانات والصلاحيات، توصية مدير التحول، اعتماد مالك العملية، واعتماد الإدارة العليا إذا أثر على تكلفة أو جدول أو سياسة.
